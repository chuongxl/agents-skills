# Stage 05 (superpowers): YOLO Commit Flow (`--yolo` only)

Load this only when `--yolo` is enabled and `speckit-code-review` is already `pass`.

## Behavior

1. Skip all human review/approval interactions.
2. Auto-generate the commit message:
   - `feat(<issue_id>): <short summary from the design spec or Jira summary>`
3. Check what is actually uncommitted, per repo, before committing there: `git status --porcelain`.
   **Empty output → skip that repo's commit and log
   `already committed during Stage 03 (<n> commits on <branch>)`.** `subagent-driven-development`
   commits per task, so a clean tree here is the normal case, not an error. Confirm the work exists
   with `git log <base-branch>..HEAD --oneline`.
4. If git submodules exist and were modified:
   - Commit each modified submodule first (when its status is dirty):
     - `git add -A`
     - `git commit -m "<auto-generated-commit-message>"`
   - Then, in the parent repo, commit the submodule pointer update and any parent changes. Re-check
     the parent's status **after** the submodule commits — those commits dirty the parent pointer:
     - `git add -A`
     - `git commit -m "<auto-generated-commit-message>"`
5. If no submodules were modified and the tree is dirty:
   - `git add -A`
   - `git commit -m "<auto-generated-commit-message>"`
6. Report the commit message + hash. If nothing needed committing, report the Stage 03 commits.

## Notes

- If a commit that was actually needed fails, stop and report the exact failure. A skipped commit on
  an already-clean tree is **not** a failure and never stops the pipeline.
- `.speckit/` and `.superpowers/` must already be git-ignored (Stage 01) so `git add -A` cannot
  sweep review scratch into the commit.
- `finishing-a-development-branch` is not invoked in YOLO mode.
- The completion step (Stage 06) still runs after this stage.
